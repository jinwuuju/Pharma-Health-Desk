# 기획안 3 — 온라인 학교: 로그인·동료 리그·소통 (v1.0)

> 작성일: 2026-11-22. 대상: 진우주 기자 학교를 동료 기자들과 함께 쓰는 온라인 학교로 넓히는 작업. 결정 D013·D014.

## 0. 목표와 원칙

크롬(Google 계정)으로 로그인해, 초대받은 동료 기자들이 같은 학교에 모여 경쟁하고 소통한다.

- **오프라인 우선**: 로그인하지 않아도 혼자 학습은 지금처럼 모두 된다. 온라인은 덧붙이는 기능이다.
- **공유는 최소로**: 동료에게 보이는 것은 닉네임, 주간 점수 요약, 연속 학습일, 설치 단계 수준, 내가 공개한 글·댓글뿐. 카드별 학습 기록, 취재 수첩, 설정은 공유하지 않는다.
- **학습을 돕는 경쟁**: 점수는 학습 행동(복습·레슨·적용)에서만 나온다. 매주 리셋, 강등 없음, 순위 옆에 ‘지난주의 나’ 비교를 함께 둔다. 기획안 1의 7.2(타인 리그 없음)는 ‘동료 리그는 선택 참여’로 바꾼다(D013).
- **초대제**: 관리자(진우주)가 등록한 이메일만 들어온다.

## 1. 방식 선택

| 안 | 내용 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| A. Firebase | Authentication(Google 로그인) + Cloud Firestore | 크롬의 Google 계정으로 바로 로그인, 실시간 갱신, 결제 정보 없이 무료 Spark 요금제로 시작, 서버 코드 없이 보안 규칙으로 권한 관리 | 점수 조작을 서버에서 막으려면 유료 Blaze의 Cloud Functions가 필요, 문서형 데이터 설계 필요 | **채택** |
| B. Supabase | Google OAuth + Postgres(행 단위 보안) | SQL로 집계가 쉬움 | 무료 정책·OAuth 설정을 따로 확인해야 함 | 대안 |
| C. 자체 서버 | — | 자유도 | 운영·보안 부담 | 제외 |

무료 한도(2026-11 Firebase 요금 문서 기준, 착수 시 재확인): Firestore 하루 문서 읽기 5만·쓰기 2만, Google 같은 소셜 로그인은 무료. 동료 30명이 하루 300번씩 읽어도 9,000회로 한도 안이다.

## 2. 기술 구조

- 앱은 지금처럼 GitHub Pages. Firebase는 로그인과 공유 데이터만 맡는다.
- SDK: Firebase 웹 SDK를 npm으로 받아 `site/vendor/firebase/`에 고정 버전 파일로 둔다(외부 CDN 금지 D003 유지). 일반 script 구조를 지키기 위해 compat 빌드를 쓴다.
- 설정값(`site/js/firebase-config.js`)은 공개돼도 되는 값이다. 접근 권한은 Firestore 보안 규칙(`firebase/firestore.rules`)이 지킨다.
- 로그인: Google 팝업 로그인. Firebase 승인 도메인에 `jinwuuju.github.io`를 넣는다. iPhone 홈 화면 앱에서 팝업이 막히면 Safari에서 로그인하도록 안내한다(O1에서 실제 기기로 확인).
- 동기화: 로그인했을 때만 주간 점수 요약·오늘의 문제 결과를 올린다. 오프라인이면 기기에 모아 두었다가 다음 접속 때 올린다.
- Firestore 위치: `asia-northeast3`(서울). 만들 때 고르며 나중에 바꿀 수 없다.

## 3. 데이터 구조 (Firestore)

```
schools/{schoolId}                                   학교 이름, 만든 날, 관리자 uid
schools/{schoolId}/invites/{email}                   초대(관리자만 쓰기)
schools/{schoolId}/members/{uid}                     닉네임, 소속(선택), 가입일, 역할(admin·member), 공개 설정
schools/{schoolId}/weeks/{weekId}/scores/{uid}       주간 XP, 복습 수, 레슨 수, 적용 수, 연속 학습일, 갱신 시각
schools/{schoolId}/daily/{date}/results/{uid}        오늘의 문제 결과(점수, 시도 수, 결과 그리드)
schools/{schoolId}/threads/{threadId}                글(문제 토론·질문·첨삭 요청), 작성자, 본문, 시각
schools/{schoolId}/threads/{threadId}/comments/{id}  댓글·첨삭(루브릭 점수 선택)
users/{uid}/private/backup                           본인만 읽고 쓰는 학습 기록 백업(선택)
```
weekId는 Asia/Seoul 기준 주(월요일 04:00 시작, 앱의 하루 시작 시각과 같음).

## 4. 보안 규칙 원칙

- 읽기: 그 학교 `members`에 내 uid가 있어야 한다.
- 가입: `invites/{내 로그인 이메일}`이 있을 때만 `members/{내 uid}`를 만들 수 있다.
- 쓰기: 내 uid 문서만(점수·결과·프로필). 글·댓글은 작성자만 고치고 지우며, 관리자는 지울 수 있다.
- 값 검사: 점수는 숫자이고 상한이 있다(예: 주간 XP 0~20,000). 글 5,000자·댓글 2,000자 제한.
- `users/{uid}/private`는 본인만.
- 한계: 점수를 앱(클라이언트)이 계산하므로 마음먹으면 조작할 수 있다. 동료끼리 학습 동기를 주는 용도로는 충분하며, 필요해지면 Blaze 요금제의 서버 검증으로 바꾼다.

## 5. 기능

### 5.1 로그인·학교 (O1)
- 나 탭 → ‘온라인 학교’: Google로 로그인 → 초대된 이메일이면 닉네임을 정하고 입장, 아니면 ‘초대받지 않은 계정’ 안내.
- 관리자 화면: 초대 이메일 추가·삭제, 멤버 목록.
- 탈퇴: 내 공개 문서 삭제.
- 선택: 학습 기록 클라우드 백업(본인만 읽음) — 기기를 바꿀 때 편하다.

### 5.2 동료 리그·대결 (O2)
- 주간 리그: 월요일 04:00 리셋, XP 순위, 강등 없음, 상위 3명 배지, 내 순위 옆에 지난주의 나 비교.
- 오늘의 문제 대결: 오늘의 보도자료·오늘의 기사 교정 결과 그리드 비교. 내가 풀기 전에는 동료 결과를 숨긴다.
- 주간 퀴즈 배틀: 같은 주간 미니 시험 문항으로 정확도·시간 비교(각자 편한 시간에).
- 응원: 동료의 연속 학습일에 박수(하루 1회).

### 5.3 소통 (O3)
- 문제 토론: 문항·보도자료마다 토론 글.
- 동료 첨삭: 기사 작업실 글을 ‘첨삭 요청’으로 올리면 동료가 루브릭(기획안 2의 16.6)으로 점수와 코멘트.
- 질문 게시판, 이번 주 읽을거리 공유.
- 알림: 앱 안 배지(새 댓글·첨삭). 푸시 알림은 PWA 이후 검토.
- 운영: 글쓰기 전에 ‘취재원 실명·미공개 취재 내용·회사 내부 정보 금지’ 안내, 신고와 관리자 삭제, 실명 대신 닉네임 가능.

## 7. 진우주가 크롬에서 직접 할 일 (O1 착수 때, 약 10분)

1. 크롬에서 Firebase 콘솔(console.firebase.google.com)에 Google 계정으로 들어가 프로젝트를 만든다(예: jinwooju-reporter-school). Google 애널리틱스는 꺼도 된다.
2. Authentication → 시작하기 → 로그인 방법에서 Google을 사용 설정.
3. Authentication → 설정 → 승인된 도메인에 `jinwuuju.github.io` 추가.
4. Firestore Database → 데이터베이스 만들기 → 위치 `asia-northeast3`(서울) → 프로덕션 모드.
5. 프로젝트 설정 → 내 앱 → 웹 앱 추가 → 표시되는 firebaseConfig를 에이전트에게 붙여 준다.
6. 이 Mac 터미널에서 `firebase login`을 한 번 한다(크롬 창이 열린다). 그러면 에이전트가 보안 규칙을 배포할 수 있다.
7. 동료 초대용 Google 계정 이메일 목록을 준비한다.

## 8. 개인정보·윤리

- 수집: Google 계정 이메일(초대 확인용), 닉네임, 학습 점수 요약. 사진·연락처는 받지 않는다.
- 공개 범위: 같은 학교 멤버에게만.
- 동료에게 줄 이용 안내 1장: 무엇이 공유되고, 어떻게 탈퇴·삭제하는지.
- 회사 업무용 계정보다 개인 Google 계정을 권장(회사 정책 확인).
