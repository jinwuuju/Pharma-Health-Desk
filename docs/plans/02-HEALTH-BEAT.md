# 건강의학 기자 바이블 — 코스 2 ‘HEALTH BEAT’ 백과·학습 통합 기획안 (v2.0)

> 작성일: 2026-11-22 (v1.0을 대체)
> 짝 문서: 「제약바이오기자_대학원준비_학습앱_기획안.md」(이하 ‘기획안 1’, 코스 1 ‘PIPELINE’)
> 대상 AI: 이 문서로 (1) 건강의학 백과(바이블)를 단계적으로 구축하고 (2) 그 위에 학습 경로와 기사 실습을 얹어 (3) 기획안 1의 앱에 두 번째 코스로 구현하는 AI

## v1.0 → v2.0 변경 요약
1. 성격 변경: 6개월 코스 → 평생 쓰는 ‘기자의 의학 바이블’. 백과(정본) 위에 학습 경로를 얹는 3계층 구조(섹션 1).
2. 질환 선정 기준 확장: 사망 부담 + 의료 이용(외래·입원 다빈도) + 뉴스 가치의 3개 렌즈(4.4).
3. 의료 이용 다빈도 질환 12개를 필수로 추가(5.3): 치주질환, 급성 기관지염·상기도감염, 알레르기 비염, 위염·기능성 소화불량, 위식도역류, 노년 백내장, 감염성 장염, 척추질환, 어깨 질환, 갑상선 질환, 두통·어지럼, 피부염·두드러기.
4. 특별 단원(Tier S) 6개 신설, 그중 비만·비만치료제를 최우선 정밀 단원으로(섹션 6).
5. 항목 유형 14종(질환 외에 증상·검사·치료·제도·쟁점·집단·생활요인 등)과 바이블식 주소 체계(4.1~4.2).
6. 통계 레지스트리: 숫자는 한 곳에만 저장하고 모든 항목이 참조(4.6).
7. 개정 체계: 항목별 버전·개정 이력·상태 워크플로(4.7).
8. 커리큘럼에 ‘금요 외래’ 트랙 26회, 비만 특별 주간, 연간 통독 플랜 추가(섹션 8).
9. 앱에 ‘백과’ 탭: 검색(초성 포함), 색인, 항목 페이지, 관계 지도, 비교, 개정 이력, 취재 전 브리핑, 내 취재 수첩(섹션 11).
10. 콘텐츠 생산 파이프라인과 확장 로드맵(섹션 15).

## 0. 이 문서를 읽는 AI에게 (필독)
- 대규모·장기 프로젝트다. 한 번에 다 만들지 않는다. 섹션 15의 생산 순서(마스터 색인 → 통계 레지스트리 → 항목 배치 생성 → 감수 → 확인 → 파생 학습 콘텐츠 → 가져오기)를 지킨다.
- 백과 항목이 정본(source of truth)이다. 카드·문제·게임은 항목에서 파생된다. 항목을 고치면 파생물도 다시 만든다.
- 앱 엔진은 기획안 1(섹션 9~11)을 공유한다. 이 문서는 차이점과 추가 기능을 정의한다. 두 문서를 함께 첨부받아야 한다.
- 학습자는 의대생이 아니라 기자다. 모든 지식은 기사 작성·인터뷰·기획에 쓰이는 깊이까지만(섹션 2).
- 의학·통계·제도·시장 정보는 바뀐다. 기준일·출처·재검토일(reviewBy)을 붙이고, 확신이 없으면 needsVerification.
- 약 용량·처방·진단 알고리즘처럼 진료 행위에 해당하는 내용은 만들지 않는다.
- 정책 쟁점은 여러 입장을 근거와 함께 균형 있게 다루고 결론을 대신 내리지 않는다.

## 1. 비전과 아키텍처

### 1.1 한 줄 정의
건강의학 기자가 평생 펼쳐 보고, 반복해 읽고, 계속 개정하는 ‘기자의 의학 바이블’. 그 위에서 인체·질환 기본기는 건강기자 5~7년차, 제약·바이오 기사 작성은 1~3년차 수준까지 체화시키는 학습 시스템.

### 1.2 3계층 + 1 기반 구조
| 계층 | 이름 | 역할 | 비유 |
|---|---|---|---|
| L1 | 백과(Canon) | 템플릿으로 작성된 항목 정본: 질환·증상·검사·치료·제도·쟁점 등 | 성경 본문 / 백과사전 |
| L2 | 학습(Paths) | 백과를 지나가는 경로: 기본편·실력편·실전편·금요 외래·주제 트랙·연간 통독 | 읽기 플랜 / 교과 과정 |
| L3 | 데스크(Desk) | 기사 작업실·인터뷰 연습실·기획 회의실·내 취재 수첩 | 실전 노트 |
| 기반 | 통계 레지스트리(Numbers) | 모든 수치를 한 곳에 저장, 항목이 참조 | 부록 통계표 |

### 1.3 두 개의 목표 수준
| 영역 | 목표 | 의미 |
|---|---|---|
| 인체·질환·의료 시스템 | 건강의학 기자 5~7년차 | 전문가 도움 없이 질환 해설의 뼈대를 쓰고, 전문의 인터뷰에서 2·3차 질문을 즉석에서 던지며, 한 질환으로 다각도 기획 시리즈를 짠다 |
| 제약·바이오 기사 작성 | 제약 전문기자 1~3년차 | 보도자료·공시·학회 발표를 정확한 스트레이트로 빠르게 바꾸고, 유형별 기사 공식을 체화했으며, 기본 해설 기사를 쓴다 |

## 2. 깊이 기준 — 의대생이 아니라 기자다

### 2.1 기자용 깊이 4단계 (모든 섹션에 depth 표시)
| 단계 | 코드 | 기자가 할 수 있어야 하는 것 | 예: 심방세동 |
|---|---|---|---|
| D1 용어 | term | 정확한 명칭·표기로 틀리지 않게 쓴다 | 심방세동(Atrial Fibrillation, AF)이 무엇인지 한 문장 |
| D2 기전 | mechanism | 독자에게 한 문단으로 원리를 설명한다 | 심방이 불규칙하게 떨려 피가 고이고 혈전이 생겨 뇌졸중 위험이 커진다 |
| D3 쟁점 | issue | 근거 수준·논쟁·최신 변화를 알고 2차 질문을 던진다 | 항응고 치료의 이득과 출혈 위험, 웨어러블 선별검사의 득실 |
| D4 기획 | planning | 다른 주제와 엮어 기획 각도를 만든다 | 고령화와 숨은 심방세동, 뇌졸중 예방 사각지대, 기기 산업 |
목표 분포: D1 25%, D2 40%, D3 25%, D4 10%.

### 2.2 필요도·용도 태그
- need: must(모르면 오류·인터뷰 막힘, 70%) / good(깊이·차별성, 30%).
- use: write / interview / plan 중 하나 이상. 용도를 댈 수 없는 지식은 만들지 않는다.

### 2.3 티어 (항목의 상세도)
| 티어 | 대상 | 상세도 | 분량(질환 기준) |
|---|---|---|---|
| S 특별 단원 | 한국 건강 기사의 상수 6개 | 12문 + 확장 모듈 10개(섹션 6) | 15,000~25,000자 |
| A 필수 심화 | 렌즈 상위 질환 | 12문 전체 | 5,000~8,000자 |
| B 표준 | 자주 다뤄지는 질환 | 12문 압축 | 2,500~4,000자 |
| C 요약 | 희귀·드문 주제 | 6문(정의·기전·규모·치료 큰 줄기·쟁점·기자 포인트) | 800~1,500자 |

### 2.4 다루지 않는 것 (의대 영역)
세부 해부(근육 기시·정지, 신경·혈관 분지) / 효소 이름을 외우는 생화학 경로 / 약물 용량·투약법·처방 / 감별진단 알고리즘 / 수술 술기 세부 / 조직병리 미세 소견 / 의사국가시험식 증례 문제.
대신 기자의 질문으로 바꾼다: 누구에게, 얼마나 효과가 있고, 근거는 얼마나 튼튼하며, 비용·접근성은 어떤가.

## 3. 목표 수준 정의 (Exit Criteria)

### 3.1 연차별 역량 사다리
| 역량 | 수습 | 1~3년차 | 5~7년차(목표) | 데스크 |
|---|---|---|---|---|
| 인체·질환 이해 | 용어를 찾아 쓴다 | 자료를 보며 설명 | 필수 질환 50개를 자료 없이 기전·쟁점까지 | 분야 간 연결·전망 |
| 숫자 감각 | 받아 적는다 | 출처 확인 | 주요 통계의 크기·추세·기준년도를 안다 | 숫자의 함정을 잡는다 |
| 취재 | 보도자료 의존 | 1차 확인 전화 | 독립 전문가·데이터로 교차검증 | 단독·탐사 설계 |
| 인터뷰 | 준비된 질문만 | 후속 질문 일부 | 근거·비교·한계를 파고드는 2·3차 질문 | 인터뷰로 기획을 끌어냄 |
| 기획 | 받은 아이템 | 단발 기획 | 질환 하나로 5개 각도 시리즈 | 연간 기획 |
| 기사 작성 | 스트레이트 틀 | 유형별 공식 | 해설·기획 구조를 자유롭게 | 데스킹 |

### 3.2 통과 기준 (앱의 ‘준비도’ 체크리스트)
인체·질환 (5~7년차)
1. 인체 10개 계통을 그림 한 장으로 그리고 계통 8문으로 각 2분 설명
2. 필수 질환 50개(Tier S·A)를 질환 12문으로 각 60초 브리핑, 자기 평가 80점 이상
3. 의료 이용 다빈도 질환 12개를 ‘독자 질문형’으로 3분 설명
4. 건강검진 결과지 주요 항목 20개 의미 설명
5. 주요 통계 출처 12곳을 알고, 원하는 수치를 10분 안에 찾아 기준년도와 함께 인용
6. 진료지침의 권고 등급·근거 수준을 읽는다
7. 민감도·특이도·양성예측도로 검진 논쟁을 설명
8. 혼동 쌍 40개를 10초 안에 구분
9. 인터뷰 시뮬레이션에서 2단 이상 질문 비율 40% 이상
10. 질환 하나로 5개 각도 기획안 1장을 40분 안에 작성
11. 보도 준칙(자살예방·정신건강·감염병 등) 준수, 흔한 오보 패턴 40개 식별
12. 비만·비만치료제 특별 단원 종합 시험 85% 이상
제약·바이오 기사 작성 (1~3년차)
13. 보도자료 → 스트레이트 600자를 30분 안에, 사실 오류 0
14. 5대 유형(임상·허가·급여·기술이전·실적) 기사 공식을 템플릿 없이 적용
15. 제목·리드 루브릭 80점 이상, 표기 원칙 위반 0
16. 포트폴리오 기사 16편(스트레이트 8, 해설 4, 인터뷰 2, 기획 2)
바이블 활용
17. 처음 맡은 질환 주제도 백과의 ‘취재 전 브리핑’으로 10분 안에 인터뷰 질문 10개를 준비

### 4.2 바이블식 주소 체계
- 형식: HB-{유형코드}-{4자리 번호} §{문항 2자리}. 예: HB-DZ-0012 §07 = 질환 12번 항목의 7문(치료).
- 번호는 마스터 색인(15.2 단계 0)에서 한 번 부여하면 바꾸지 않는다. 항목을 폐기해도 번호는 재사용하지 않는다(deprecated 표시).
- 앱 주소창에 주소를 입력하면 해당 절로 이동. 기사 메모·취재 수첩에서 주소로 인용.
- 코스 1 항목은 PL-{유형}-{번호} 형식(통합 시 사용).

### 4.3 관계 그래프
링크 유형: partOf(기관→계통) / riskFactorOf / causes / complicationOf / symptomOf / diagnosedBy(검사) / treatedBy(치료) / confusableWith(혼동 쌍) / issueOf(쟁점↔질환) / governedBy(제도) / affects(생활요인→질환) / populationOf(집단) / pipelineLink(코스 1) / seeAlso.
최소 기준: 질환 항목은 계통 1, 검사 2, 치료 2, 혼동 쌍 1, 제도 또는 쟁점 1개 이상과 연결. 링크는 양방향 저장(백링크 자동 생성).

### 4.4 항목 선정 3렌즈
| 렌즈 | 질문 | 근거 데이터 |
|---|---|---|
| 사망·질병 부담 | 사람을 가장 많이 죽게 하거나 장애를 남기는가 | 사망원인통계, 질병부담 연구 |
| 의료 이용 | 사람들이 병원을 가장 많이 찾고 돈이 가장 많이 드는가 | 외래·입원 다빈도 질병 통계, 건강보험 진료비 통계 |
| 뉴스 가치 | 정책·산업·사회적 관심이 큰가 | 보도량, 정책 의제, 신약·시장 동향 |
모든 질환 항목에 lenses 태그. 두 렌즈 이상이면 Tier A 이상 후보, 세 렌즈 모두면 Tier S 후보.

### 4.5 티어 배정 규칙
- Tier S: 세 렌즈 모두 상위 + 연중 상시 등장 + 산업·정책이 함께 움직임.
- Tier A: 두 렌즈 이상 상위, 또는 한 렌즈 최상위(예: 외래 1위 치주질환, 입원 1위 노년 백내장).
- Tier B: 한 렌즈 상위권 또는 계절·생활 기사에 자주 등장.
- Tier C: 희귀질환·신약 뉴스로만 등장하는 질환 등.
- 매년 통계 갱신 후 티어 재검토(승급·강등 기록).

### 4.6 통계 레지스트리 — 숫자는 한 곳에만 산다
- 모든 수치는 StatRecord 하나로 저장: 값, 단위, 대상 집단, 기간(기준년도), 지표 정의, 출처 기관·자료명·URL, 발표일, 다음 발표 예정, 재검토일.
- 항목 본문은 숫자를 직접 쓰지 않고 토큰 {{ST-0123}}으로 참조. 앱이 값·단위·(기준년도, 출처)로 렌더링하고, 재검토일이 지나면 주황 배지.
- 통계 하나를 고치면 그 통계를 참조하는 모든 항목·카드·게임 문항에 ‘갱신됨’ 표시(전파).
- 발표 캘린더: 기관별 정기 발표 시기를 기록(예: 최근 2년 기준 심평원 다빈도 질병 통계는 6월, 사망원인통계는 9월 무렵 — 매년 확인). 발표 주간에 ‘갱신 과제’ 자동 생성.
- 같은 지표가 출처마다 다르면(예: 조사 기반 유병률 vs 건강보험 진료인원) 별도 레코드로 두고 정의 차이를 note에 기록.

### 4.7 개정 체계
- 항목 버전: 주.부(1.0 → 1.1 소폭 수정, 2.0 지침 개정 반영).
- 개정 이력(Revision): 날짜, 변경 내용, 사유(통계 갱신 / 지침 개정 / 오류 정정 / 확장), 작성 주체(AI·학습자·전문가).
- 상태 워크플로: planned → draft → reviewed(AI 감수) → verified(학습자 확인) → published → needs-update → (개정) → published / deprecated.
- 개정 주기: 통계 항목은 발표 시, 지침·제도 항목은 연 1회 정기 점검 + 사건 발생 시 수시, 쟁점 항목은 분기 점검.
- 연 1회 ‘개정판’ 발행: 그해 바뀐 항목 목록과 요약(앱의 ‘올해의 개정’), 개정 사항만 모은 회독 플랜 자동 생성.

## 7. 정석 공식 — 기사·인터뷰·기획 (백과 부록 E~H로도 수록)

### 7.1 기사 공식 (WR) — 유형별 4요소
1) 일반 스트레이트 — 리드: 누가+무엇을+언제(+왜 중요한지), 한 문장 60자 내외. 순서: 리드 → 핵심 사실 보강 → 배경 → 반응·맥락 → 향후 일정(역피라미드). 필수 확인: 6하원칙, 출처, 숫자 단위·기준.
2) 임상 결과 — 리드: 회사+후보물질(코드명·계열)+적응증+임상 단계+1차 평가변수 결과를 절대 수치로. 순서: 리드 → 설계(대상자 수·대조군·무작위·맹검·1차 평가변수) → 결과(효과 크기·신뢰구간·p값) → 안전성 → 의미와 한계(독립 시각) → 향후 계획. 필수 확인: 탑라인 여부, 1차 평가변수 충족, 사전 지정 분석, 출처(학회·논문·보도자료), 비교 대상. 금지: 효과 입증(단일·탐색적), n배 효과(상대 수치만), 부작용 없음.
3) 허가 — 리드: 기관+제품명(성분명)+적응증 범위+허가 유형. 필수 확인: 신청 접수/임상시험계획 승인/품목허가/급여 등재 구분, 가속·조건부 여부, 근거 임상, 출시·가격·급여 미정이면 미정이라고.
4) 급여·약가 — 리드: 약제+적응증+급여 적용 시점+환자 부담 변화. 필수 확인: 평가→협상→고시 중 단계, 급여 기준, 위험분담제 여부, 본인부담 계산 기준.
5) 기술이전·계약 — 리드: 회사+상대 회사+물질(단계)+‘계약금 OO억원 포함 최대 OO억원’. 필수 확인: 공시 원문, 계약금·마일스톤·로열티 분리, 권리 범위, 반환 조건, 환율 기준일. 금지: 총규모를 확정 수익처럼, 잭팟.
6) 실적·투자 — 리드: 회사+기간+매출·영업이익+전년 대비. 필수 확인: 연결·별도, 일회성 요인, R&D 비용, 기술료 수익. 금지: 매수·매도 권유, 주가 전망 단정.
7) 질환 해설 — 구조: 무엇인가 → 왜 생기나 → 누가 위험한가 → 어떤 신호 → 어떻게 확인 → 어떻게 치료 → 어떻게 예방 → 어디서 도움. 필수 확인: 진단 기준 출처, 통계 기준년도, 독립 전문가 2인 이상, 과장 없는 치료 기대치.
8) 계절·생활 건강(금요 외래 연계) — 구조: 시의성(계절·통계) → 흔한 오해 바로잡기 → 위험 신호와 진료 시점 → 근거 있는 관리법 → 출처. 필수 확인: ‘OO에 좋은’ 단정 금지, 제품 광고성 배제.
9) 인터뷰(Q&A) — 구조: 인물 소개 리드 → 핵심 메시지 → Q&A 6~10 → 마무리. 필수 확인: 인용 정확성, 용어 풀이, 이해상충.
10) 기획 시리즈 — 구조: 문제 제기(데이터·현장) → 원인 → 해외·대안 → 제언. 필수 확인: 데이터 교차검증, 반론 취재, 당사자 동의.
11) 정책·제도 — 구조: 무엇이 바뀌나 → 누가 영향받나(숫자) → 왜(정부 설명) → 반대·우려(이해관계자) → 시행 일정·남은 절차. 필수 확인: 확정·예고·검토 단계 구분, 법령·고시 원문.
12) 위기·안전(부작용·회수·임상 중단) — 구조: 확인된 사실 → 당국 조치 → 환자 행동 요령(임의 중단 금지 등 전문가 확인) → 아직 모르는 것. 필수 확인: 당국 공식 자료, 공포 조장 표현 배제.

### 7.2 인터뷰 질문 사다리
1단 사실(무엇이, 얼마나) → 2단 근거(어떤 연구·설계·규모) → 3단 비교(기존 치료·해외·대조군) → 4단 한계(모르는 것·반대 의견·위험) → 5단 의미(환자·제도·산업). + 이해상충 질문(관련 기업 자문·연구비). 앱은 질문에 단계 태그를 붙여 2단 이상 비율을 측정한다.

## 11. 앱 기능 명세 (기획안 1 대비 추가·변경)

### 11.1 멀티 코스
- 상단 세그먼트: PIPELINE(코스 1) | HEALTH BEAT(코스 2) | 통합. 통합 보기는 두 코스 세션을 각각 카드로, 링은 합산.
- 복습 한도는 코스별(기본 코스 1 80 + 코스 2 40). 모든 데이터에 courseId.

### 11.2 탭 (코스 2)
| 탭 | 역할 |
|---|---|
| 오늘 | 출퇴근 세션, 금요 외래, 오늘의 통독 항목, 링, 스트릭 |
| 백과 | 검색·색인·항목·관계 지도·비교·개정·취재 전 브리핑 |
| 학습 | 인체·질환 지도, 복습(카드·빈칸·매칭·러시·백지·브리핑), 회독·주제 트랙 |
| 작업실 | 기사 작업실·인터뷰 연습실·기획 회의실·포트폴리오·취재 수첩 |
| 나 | 연차 준비도, 회독 비교, 보정 그래프, 통계 갱신 대기, 생산 현황(15.6) |

### 11.3 백과 탭
- 검색: 표제어·별칭·영문·약어·질병분류 코드·본문 전문. 한글 초성 검색(예: ㄷㄴㅂ → 당뇨병). 동의어 사전(예: 당뇨, 2형 당뇨, T2DM). 오프라인 인덱스.
- 색인: 가나다 / 유형별 / 계통별 / 티어별 / 렌즈별 / 최근 개정순 / 통계 갱신 필요순.
- 주소 이동: HB-DZ-0012 §07 입력 → 해당 절로 이동·강조.
- 항목 페이지: 상단(표제·주소·티어·렌즈·버전·상태·최종 갱신일) → 핵심 요약 3줄 → 문항별 접기·펼치기 → 통계 토큰은 값과 (기준년도, 출처) 배지(재검토일 경과 시 주황) → 관계 패널(링크 유형별) → 백링크 → 출처 → 개정 이력 → ‘학습에 추가’(파생 카드 등록) → 끝에 떠올리기 질문 3개.
- 떠올려 보기 모드: 본문을 가린 채 문항만 보고 먼저 떠올린 뒤 펼쳐 자기 평가.
- 관계 지도: 선택 항목 중심 SVG 그래프(1~2단계 이웃), 링크 유형별 색, 노드 탭으로 이동.
- 비교 모드: 같은 유형 2~4개 항목을 템플릿 문항별 표로 나란히(예: 뇌경색 vs 뇌출혈, GLP-1 작용제 계열 vs 이중 작용제 계열 — 제품 순위가 아니라 계열·근거 비교).
- 개정: 항목 버전 비교(바뀐 문장 강조), ‘올해의 개정’ 목록.
- 취재 전 브리핑: 한 번에 1장 요약(핵심 3줄, 최신 통계 5, 쟁점 3, 인터뷰 질문 10, 오보 주의 3, 코스 1 연결, 취재원 유형) → 마크다운 복사·인쇄.
- 다시 볼 구절: 형광펜 대신 표시만 하고 통독·복습 때 재노출(다시 읽기만 하는 기능은 두지 않음).

### 11.4 내 취재 수첩 (개인 레이어)
- 항목·절마다 개인 기록: 메모 / 현장에서 들은 것(미검증 표시) / 내 기사 링크 / 취재원 기록(이름·소속·분야·연락 경로).
- 취재원 기록은 로컬에만 저장, 백업 내보내기에서 기본 제외(선택 포함), 화면 잠금 옵션, 개인정보 주의 안내.
- 수첩은 백과 본문과 시각적으로 구분(정본과 개인 기록 분리).

### 11.5 연차 마스터리 라벨 (규칙은 기획안 1의 11.2와 동일)
미취재(discovery) → 수습(preclinical) → 1년차(p1) → 3년차(p2) → 5년차(p3) → 7년차(approved) → 데스크(p4). 복습 오답 시 ‘정정보도’ 표시와 함께 3년차로 강등. 항목 연차 = 그 항목 파생 카드의 하위 25% 지점.

### 11.6 인체 지도
정면 인체 실루엣 SVG(직접 그린 단순 도형, 외부 이미지 금지)에 계통 레이어 토글. 탐색 모드(기관 탭 → 기관 항목 요약), 퀴즈 모드(위치 맞히기, 기능 역질문), 기관에서 관련 질환으로 이동.

### 11.7 백지 모드
항목 선택(또는 무작위) → 5분 자유 입력 → 템플릿 문항별 핵심어와 대조해 커버리지 산출 → 빠진 문항 강조·카드 즉시 복습 → 회독별 기록.

### 11.8 60초 브리핑
무작위 항목 → 10초 준비 → 60초 녹음(로컬 저장) → 자기 체크(정의·기전·규모와 기준년도·위험군·치료 큰 줄기·쟁점·시간) → 매주 월요일 자동 출제.

### 11.9 게임
- 오늘의 기사 교정(Wordle형): 하루 1건 가상 건강·제약 기사, 오류 3~5개(사실, 숫자 단위, 상대위험만 제시, 낙인 표현, 보도 준칙, 허가·급여 혼동 등), 6회 선택, 교정본 제시.
- 숫자 감각 게서(GeoGuessr형): 레지스트리에서 출제, 근접도 점수, 재검토일 지난 레코드는 제외.
- 용어 러시: 3분, 의학 용어 ↔ 쉬운 말, 약어 풀이, 오답 3번 종료.
- 매칭: 기관↔기능, 질환↔기전, 검사↔목적, 업무↔담당 기관.
- 정렬: 혈액 순환, 소화 경로, 뇌졸중 의심 시 대응, 보도자료 처리, 급여 등재 절차.
- 제목 클리닉: 제목 4개 중 정확하면서 읽히는 것 고르기 → 직접 쓰기.
- 다빈도 랭킹 퀴즈: 외래·입원 다빈도 순위 맞히기(레지스트리 기반, 기준년도 표시).

### 11.10 기사 작업실 (마감 시뮬레이터)
과제(유형·자료·분량·마감) → 편집기(글자 수, 남은 시간, 기사 공식 패널 — 숙련 시 숨김) → 실시간 점검(금지 표현, 숫자의 단위·기준 누락, 첫 약어 풀이 누락, 보도 준칙 경고) → 루브릭 자기 채점 → 모범 기사·나쁜 예와 비교 → AI 첨삭 프롬프트 복사 → 포트폴리오 저장. 하위 드릴(리드·제목·숫자 문장 각 10개). 백과 항목을 옆 창에 띄워 참조 가능(취재 상황 재현), 참조한 절은 기사 메모에 주소로 남김.

### 11.11 인터뷰 연습실
분기형 시나리오(사다리 단계 태그, 얻어낸 정보 점수), 질문지 설계 모드(15분 15문항, 2단 이상 40% 목표), AI 롤플레이 프롬프트 복사, 환자·보호자 인터뷰 윤리 체크리스트(동의, 신원 보호, 2차 피해, 사진·실명, 미성년자).

### 11.12 기획 회의실

## 14. 알고리즘 (기획안 1의 11.1~11.4 + 추가)
- 통계 토큰 렌더링: 본문 {{ST-xxxx}}를 레지스트리 값으로 치환해 ‘값 단위(기간, 출처)’로 표시. 레코드가 없으면 빨간 ‘누락’ 배지, reviewBy 경과 시 주황.
- 갱신 전파: StatRecord가 바뀌면 그 id를 참조하는 Entry·Card·Item에 updated 표시, 해당 카드는 다음 세션에 재출제(바뀐 지식은 다시 인출).
- 파생 규칙(항목 → 학습 콘텐츠): 문항마다 카드 1~2장(front = 템플릿 질문을 항목에 맞게, back = 핵심 2~3문장) / keywords로 빈칸 문항 / confusableWith마다 대조 문항 2 / statRefs마다 숫자 감각 문항 1 / 질환 Tier S·A 10~14문항, B 6, C 3 / 증상·검사·치료 항목 4~6. derived.generatedFromVersion에 기록하고, 항목 버전이 바뀌면 파생물을 재생성 대상으로 표시.
- 검색: 한글 음절을 초성·중성·종성으로 분해(유니코드 산술)해 초성 인덱스 생성. 순위 = 표제 일치 > 별칭 > 약어·영문·코드 > 본문(2글자 이상 부분 일치).
- 연간 통독 플랜 생성: Tier S(확장 모듈 포함, 여러 날) → A → B → 제도·쟁점 → C 순서로 365일 배분, 같은 계통이 3일 연속되지 않게 섞고, 계절 항목(호흡기 감염은 겨울, 장염은 여름, 꽃가루 알레르기는 봄)은 해당 계절에.
- 백지 복기 채점: 문항 커버리지 = 발견된 핵심어 ÷ 문항 핵심어(동의어 포함, 공백·조사 차이 무시). 전체 = 가중 평균(질환은 2·3·7·11문 가중치 1.5). 50% 미만 문항의 카드는 다음 날 강제 복습.
- 혼동 쌍: 한쪽 오답 시 짝 카드 동반 출제.
- 속도 카드: 최근 5회 정답 + 평균 6초 이하 → 러시 모드 우선 출제.
- 연차 준비도: 영역별(인체·질환·다빈도·비만·제도·기사·인터뷰·기획) 준비도를 사다리에 매핑(0~39 수습, 40~54 1~3년차, 55~69 3~5년차, 70~84 5~7년차, 85 이상 데스크), 범위로 표시.
- 티어 재검토 알림: 다빈도·사망원인 레코드 갱신 후 순위 변화가 큰 질환의 티어 재검토 과제 생성.
- 링크 검사: 가져오기 때마다 깨진 관계·누락 토큰·최소 관계 기준 미달 항목 목록 생성.

## 15. 콘텐츠 생산 파이프라인 (대규모 프로젝트 운영)

### 15.1 원칙
- 정본 먼저, 파생은 나중: 항목을 감수·확인한 뒤에만 카드·문항을 만든다.
- 숫자 먼저: 항목을 쓰기 전에 필요한 통계를 레지스트리에 넣는다. 본문은 숫자를 직접 쓰지 않는다.
- 작게 자주: 한 번에 항목 3~5개(Tier S는 모듈 2~3개)씩.
- 생성과 감수는 다른 대화(또는 다른 AI)에서. 같은 대화에서 자기 글을 감수하면 오류를 놓친다.
