# 결정 기록

> 기획안과 다르게 정했거나 기획안에 없던 것을 정할 때 D번호로 남긴다. 번호는 재사용하지 않는다.

## D001 저장소 체계 (2026-11-22)
「건강 기자 키우기」(Raise-a-Healthy-Game)와 같은 문서 체계를 쓴다: AGENTS.md(규칙·현재 위치) · STATUS(사실 기록) · NEXT-STEPS(단계 카드) · DECISIONS · 문서 지도. 어느 기기·어느 AI가 이어받아도 같은 순서로 읽고 한 단계씩 진행하게 하기 위해서다.

## D002 배포 방식 (2026-11-22)
main push → GitHub Actions에서 `tools/check_project.py` 통과 → `site/`를 그대로 GitHub Pages에 올린다. 빌드 단계가 없으므로 저장소의 `site/`가 곧 배포본이다.

## D003 기술 (2026-11-22)
바닐라 HTML·CSS·JavaScript. 패키지 관리자·번들러·외부 CDN 없음. 기획안 1의 10.1(단일 파일, file:// 동작)을 따르되, 코드가 커지면 `site/js/`, `site/css/`로 나누는 것을 허용한다.

## D004 저장 (2026-11-22)
학습 기록·콘텐츠는 IndexedDB, 설정만 localStorage. schemaVersion과 마이그레이션, 백업 JSON 내보내기·가져오기는 M1부터 필수.

## D005 한 앱 두 코스 (2026-11-22)
기획안 2의 0장 권장안을 채택한다. PIPELINE과 HEALTH BEAT를 한 앱에서 운영하고 모든 데이터에 courseId를 둔다.

## D006 설치 순서 (2026-11-22)
기획안 1의 M 순서와 기획안 2의 C·E 순서를 NEXT-STEPS 하나로 엮는다. 코스 2 학습이 W1(2026-12-07)부터 시작하므로 C1·E1·C2를 M4보다 앞에 둔다. iPhone 출퇴근 학습이 코스 2의 기본 운영이므로 PWA 설치를 M10에서 단계 9로 앞당긴다.

## D007 콘텐츠 위치 (2026-11-22)
콘텐츠 원본은 `data/`(packs·canon·registry). 앱에 기본으로 싣는 팩은 `site/packs/`로 복사한다. 앱은 두 경로(기본 탑재, 파일 가져오기) 모두로 팩을 읽는다.

## D008 공개 저장소 원칙 (2026-11-22)
GitHub Pages 무료 배포를 위해 공개 저장소로 둔다. 따라서 취재원 정보, 실명 인터뷰 메모, 회사 업무 문서(.docx·.xlsx·.hwp·.pdf), 음성 파일, 앱 백업 파일은 커밋하지 않는다. `check_project.py`가 금지 형식·이름을 검사한다. 앱의 개인 기록(취재 수첩 등)은 기기 안에만 저장한다.

## D009 기획안 기준본 (2026-11-22)
기획안 1·2의 기준본은 저장소의 `docs/plans/` 사본이다. 바탕화면 원본은 참고용이며, 개정은 저장소 사본에 버전을 올려 한다.

## D010 M1 저장 구조 (2026-11-22)
IndexedDB 이름 pharma-health-desk, 구조 버전 1. 저장소 6개: meta(key), packs(packId), content(id, 색인 packId·kind·courseId), progress(id), attempts(id), daylogs(key). 콘텐츠는 원본 객체를 {id, kind, packId, courseId, data}로 감싸 저장한다. 팩 가져오기는 같은 id를 덮어쓰고 학습 기록(progress·attempts·daylogs)은 건드리지 않는다. 같은 packId의 파트 파일은 합쳐지고, 파트에서 비어 있는 메타 값은 기존 값을 지킨다. 최상위가 배열인 파일(마스터 색인·통계 목록)은 단계 5(C1·E1)부터 받는다. 백업 파일은 app 'pharma-health-desk', kind 'backup', schemaVersion, stores, settings로 이루어지며 더 새 스키마의 백업은 거부한다. 설정은 localStorage 키 phd.settings.

## D011 개발용 앱 동작 검사 (2026-11-22)
D003(빌드 도구 없음)은 배포본(site/)에 대한 원칙이다. 개발용 검사에 한해 tools/smoke에서 npm 의존성(jsdom, fake-indexeddb)을 허용한다. Actions에서 check_project 다음에 돌리고, 통과해야 배포한다. 새 기능을 설치할 때마다 smoke.mjs에 검사 항목을 추가한다.

## D012 앱 이름 (2026-11-22)
앱 이름을 ‘진우주 기자 학교’로 한다(사용자). 화면 제목, 홈 화면 이름, 사이드바, 오늘 화면 머리말, 문서 제목에 쓴다. 저장소 이름(Pharma-Health-Desk)·공개 주소·Mac 폴더 이름·IndexedDB 이름과 백업 식별자(pharma-health-desk)는 주소와 기존 기록·백업 호환을 위해 그대로 둔다.

## D013 온라인 학교 방식 (2026-11-22)
동료 기자와 경쟁·소통하는 온라인 기능은 Firebase(Authentication의 Google 로그인 + Cloud Firestore, 무료 Spark 요금제)로 만든다. 앱은 GitHub Pages에 그대로 두고, SDK는 `site/vendor/`에 고정 버전으로 둔다(D003 유지). 초대제, 공유 최소화(닉네임·주간 점수 요약·연속 학습일·공개한 글만), 오프라인 우선. 기획안 1의 7.2(타인 리그 없음)는 ‘동료 리그는 선택 참여, 강등 없음, 매주 리셋, 지난주의 나 비교 병행’으로 바꾼다. 상세는 기획안 3.

## D014 온라인 단계 위치 (2026-11-22)
O1(로그인·학교)은 XP가 생기는 M5 다음(8a), O3(소통)는 작업실 C4 다음(13a), O2(리그·대결)는 게임 M7·C5 다음(14a)에 둔다. 사용자가 원하면 O1을 앞당길 수 있다. 진행 현황 데이터의 단계마다 표시 번호 n을 둔다.

## D015 초안 폴더·생산 순서·통계 파일 모양 (2026-11-22)
- 감수 전 생성물은 `drafts/`(같은 하위 구조)에 둔다. 새 대화에서 감수(기획안 1의 14.5, 기획안 2의 18.6)하고 사람이 사실 3개를 확인한 뒤 `data/`로 옮긴다. data/README의 ‘감수 뒤에만 넣는다’ 규칙을 지키기 위해서다.
- 단계 2는 사용자 지시로 코스 2(색인·통계)를 먼저, 코스 1(W00·W01)을 나중에 한다. 이어서 UI/UX 정돈을 단계 2a로 넣는다.
- 통계 레지스트리 파일은 StatRecord 배열 대신 CanonPack 모양(`packId`, `courseId`, `stats`, `sources`)으로 둔다. 출처를 같은 파일에 두어 sourceId를 검사할 수 있고, 지금 앱에서도 가져올 수 있다.
- 마스터 색인은 기획대로 배열로 두고(앱 가져오기는 단계 5부터), 행에 `target`(v1.0·v2.0)과 `group`(S1~S6, U1~U12)을 더한다. 계획 링크는 `관계유형:주소` 문자열.

## D017 감수는 전부 만든 뒤 일괄로 (2026-11-22)
- 사용자 지시: 감수를 기다리지 말고 콘텐츠를 바로 앱에 넣고, 전부 만든 뒤 한꺼번에 감수받는다. D015의 `drafts/` 단계는 없앤다(파일은 `data/`로 옮김).

## D018 게임형 UI/UX와 복습 엔진을 한 단계로 (2026-11-22)
- 사용자 지시: 업무 프로그램·관리자 페이지 느낌을 버리고 웹게임처럼 몰입하게. 매일 들어와 내 캐릭터를 보고, 간결한 동작, 애플식 디자인, 성공한 웹게임 로직 모방. 설계는 `docs/design/UI-PRINCIPLES.md`(D016 대체).
- 단계 2b(게임형 UI)와 단계 3(M2 복습 엔진)을 함께 했다. 복습 세션이 게임의 핵심 판(‘취재’)이기 때문이다.
- 탭을 5개 → 4개(홈·지도·도감·나)로. 시험 탭은 지도의 보스 칸으로 옮기고 옛 주소 `#/exam`은 지도로 보낸다. 관리 기능은 나 → 설정(`#/me/settings`).
- 기획안 1의 8.1(탭 5개)·9.3(오늘 탭 와이어프레임)을 이 화면 구조로 바꾼다. 3개 링은 ‘오늘의 퀘스트’ 3개로 이어받는다: 복습 정리·새 카드·콤보 7. 적용 링은 문항 엔진(M4) 뒤에 적용 문항으로 바꾼다.
- 기획안 1의 7.2 XP 표에 더한 것: 콤보 10마다 +2, 특종(정답의 8% 무작위) 그 카드 XP 2배, 퀘스트 3개 +10. 모두 학습 행동에만 준다. 레벨 n → n+1에 40 + 20n XP, 연차 이름과 장비 9개.
- 11.1에서 정하지 않은 것: 신규·학습 중 ‘쉬움’ = 4일 졸업, ‘어려움’ = 같은 학습 단계 반복. 학습 단계는 세션 안에서 1분 = 2장 뒤, 10분 = 맨 뒤에 다시 낸다(실제 시각은 dueAt에 저장). 세션을 열 때 20분 안에 돌아올 학습 카드도 함께 낸다.
- 레슨 리더(M3) 전까지는 새 카드를 취재 세션에서 바로 투입한다(하루 신규 한도). 마스터리는 1상까지만(노출 다음 날 정답), 2상 이후 승급은 문항·시험 단계(M4·M6)에서.
- 연속일 인정(11.7): 그날 대기열 0, 또는 20장, 또는 10분. 월 2회 휴가권 자동, 끊기면 3일간 재개 보너스(XP 1.5배, 세션 끝에 더함).
- 저장 구조는 바꾸지 않았다(DB v1·스키마 v1): 카드 학습 상태는 progress(kind: card), 평가 기록은 attempts, 하루 기록은 daylogs, 캐릭터 XP·연속일은 meta의 game. 설정에 sound·nickname 추가(기존 설정과 호환).

## D020 근거 2048 → 오보 지뢰찾기, 학습은 무제한 (2026-11-22)
- 사용자 피드백: 근거 합치기(2048)는 너무 어렵고 이상하다. 지뢰찾기처럼 직관적이고 재밌게. 출석은 매일 하되 하루 1개만 할 수 있게 막지 말 것.
- 근거 2048을 없애고 오보 지뢰찾기(`site/js/mines.js`)로 바꿨다. 고전 규칙(숫자·깃발·첫 칸 안전·숫자 칸 다시 눌러 주변 열기)에 함정 = 오보 유형 16종. 밟으면 3지선다, 맞히면 해체(+2 XP), 틀리면 ❤️ −1, 3개를 잃으면 판 종료. 승리 XP 수습 5·기자 8·데스크 12 + 별(밟지 않음 3·모두 해체 2·그 외 1)−1.
- 함정은 게임 팩의 새 묶음 traps(16, 생성기 안이 원본)이고, 만나면 함정 카드(unlock tr)와 관련 근거 사다리 단계 카드(ev)가 함께 열린다. 근거 사다리 10단계 카드는 그대로 두고 여는 길만 바꿨다. 옛 2048 판(meta g2048)은 쓰지 않지만 지우지 않는다.
- 오늘의 진단·숫자: 하루 한 문제는 그대로(출석·기록·공유). 끝나면 ‘한 문제 더’ 연습을 무제한으로(아직 발견하지 못한 것부터, 기록과 별개, 정답 3·도전 1 XP, 퀘스트 ‘오늘의 퍼즐’에는 세지 않음).
- 홈의 큰 버튼은 할 일이 끝나도 ‘새 카드 5장 더’ 또는 ‘오보 지뢰찾기 한 판’으로 이어진다. 도감에서 발견했지만 아직 취재하지 않은 카드는 ‘발견(별 0)’으로 보인다.
- 게임 팩 HB-GAME-001 버전 2026-11-22.2(카드 236). 탭 이름 ‘근거’ → ‘지뢰찾기’.

## D021 오보찾기: 문제 은행 하나, 클래식 게임 5종 (2026-11-22)
- 사용자: 오보 지뢰찾기를 고도화하고 콘텐츠를 많이. 이름은 ‘오보찾기’. 실제로 기자가 헷갈리는 지점으로, 해설을 잘. 지뢰찾기 말고 다른 클래식 중독 게임도 — 퀴즈는 같고 형식만 바꿔 안 질리게. 선지가 뻔하다(대부분 긴 게 정답) — 난도는 내용이 아니라 선지로 올려라.
- 문제 은행 `tools/hb_ohbo_bank.py` 59문항(연구 설계 9·숫자·통계 14·임상·신약 11·허가·제도 7·의학 용어 5·표현·윤리 9·출처·시점 4, 난도 1·2·3 = 11·32·16). 4지선다, 선지마다 해설, 고쳐 쓰기, 기자 체크, O/X 문장(문제 문장=오보, 고쳐 쓰기=정확, 일부 추가). 기존 함정 16개 id는 유지(발견 기록 호환).
- 선지 길이 균형: 생성기가 ‘정답이 가장 긴 선지’ 수를 출력하고, 스모크 검사가 25% 미만인지 본다. 처음 68%(40/59)였던 것을 문장을 다듬어 3%(2/59)로 낮췄다. 정답 길이 순위가 고르게 퍼지게 했다.
- 게임 5종(`quiz.js` 공통 엔진): 지뢰찾기(mines.js, 4지선다로 바뀜), 퀴즈쇼(백만장자형 12단계·안전 지점 2개·찬스 3개), 속보 러시(90초·3스트라이크·스와이프 O/X), 짝 맞추기(6쌍), 스네이크(A~D 먹이). 허브에 오늘의 게임(날마다 순환), 오답 노트(최근 틀린 60문항). 게임 화면에선 탭바를 숨긴다(데스크톱 사이드바는 유지).
- XP: 게임 끝에 맞힌 만큼(퀴즈쇼: 맞힌 수+도달 단계, 우승 +10 / 러시: 점수÷2 / 짝: 3+별 / 스네이크: 점수+2), 최고 기록 +3, 새로 알게 된 문항은 ‘새 발견’으로 센다. 기록은 meta `quiz`(문항별 맞힘·틀림·최근, 최고 기록, 오답 노트).
