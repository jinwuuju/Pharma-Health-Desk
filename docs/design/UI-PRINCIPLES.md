# UI 원칙 — 애플식 기본 + 간결·효율 사례 5개 (D016)

> 2026-11-22. 사용자 요청: 애플식을 기본으로, 간결하면서 체계적·효율적으로. 군더더기 없이 깔끔하고 세련되게, 잘 정돈된 화면.

## 기본: Apple Human Interface Guidelines
큰 제목, 그룹 목록, 44pt 이상 터치 영역, 시스템 글꼴, 반투명 탭바, 라이트·다크·자동. 토큰은 기획안 1의 9.2(`site/css/app.css` 맨 위).

## 화면을 만들 때 지킬 규칙
1. 화면마다 주 행동은 하나(파란 버튼 1개). 보조 행동은 회색 버튼.
2. 색은 의미에만: 파랑 = 행동·현재, 빨강 = 위험·삭제, 링 3색 = 지표, 파랑·민트 = 코스 구분. 장식용 색·그림자는 쓰지 않는다.
3. 정보 순서: 지금 할 일 → 진행 상황 → 일정 → 기록.
4. 숫자는 큰 숫자 + 작은 라벨, 고정폭 숫자(tabular-nums).
5. 목록은 그룹 목록, 행 44px 이상, 값은 오른쪽 정렬, 구분선은 머리카락 두께.
6. 안내 문장은 한 줄. 긴 설명은 펼치기나 시트로.
7. 키보드: 숫자 탭 이동, Esc 닫기. 예정: ⌘K 검색(E2), 복습 플레이어 Space 뒤집기·1~4 평가(M2).
8. 움직임은 짧게(0.12~0.25초), ‘동작 줄이기’ 설정을 존중한다.
9. 간격은 4의 배수(`--s1`~`--s6`).

## 이번에 바꾼 것 (전 → 후)
- 오늘 화면
  - 전: 앱 이름이 들어간 머리말 → 링 카드와 두 문장 안내 → D-day 큰 카드 2~3개 → 콘텐츠 숫자와 관리 버튼.
  - 후: 날짜 머리말 → ‘다음 일정’ 카드와 주 버튼(레슨 보기), 콘텐츠가 없으면 빈 상태(샘플·가져오기) → 오늘의 링(안내 한 줄) → 학습 일정 목록(가장 가까운 일정만 파란색) → 가져온 콘텐츠 큰 숫자.
- 탭: 숫자 1~5로 이동. 데스크톱 사이드바에 단축키 표시, 마우스를 올리면 배경 표시.
- 공통: 버튼 누름 반응(살짝 줄어듦), 목록·버튼 hover, 고정폭 숫자, 간격 토큰, 동작 줄이기 대응.

## 사람 확인
Mac Safari·Chrome, iPhone Safari에서 라이트·다크 모두 본다. 다음 일정 카드가 화면 첫 줄에 보이는지, 학습 일정의 파란 값이 하나뿐인지, 숫자 키 이동이 입력창에서는 동작하지 않는지 확인한다.
