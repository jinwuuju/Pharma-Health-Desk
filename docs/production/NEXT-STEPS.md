# 다음 단계 — 한 단계씩 설치하기

> 체크되지 않은 첫 단계가 ‘지금 할 단계’다. 한 번에 한 단계만 한다.
> 단계마다: 범위 / 기준 문서 / 완료 확인 / 사람 확인.

## 이어서 할 때 한 줄

> **“AGENTS.md를 읽고 NEXT-STEPS.md의 다음 단계를 진행해줘.”**

### 새 채팅에서 이어갈 때 (Mac을 제어할 수 있는 AI에게 그대로 붙여넣기)
```
내 Mac의 ~/제약헬스 기자 데스크 저장소(github.com/jinwuuju/Pharma-Health-Desk)에서 이어서 작업한다.
터미널로 git pull 한 뒤 AGENTS.md → docs/production/STATUS.md 맨 위 → docs/production/NEXT-STEPS.md 순서로 읽고,
체크 안 된 다음 단계 하나만 진행해줘. 끝나면 AGENTS.md 3절대로 검사·기록·push·배포 확인까지 하고,
바뀐 것과 내가 직접 확인할 것만 짧게 알려줘.
```

### 방법 A — 코딩 에이전트 (권장)
1. 터미널에서 `cd ~/'제약헬스 기자 데스크'` 후 코딩 에이전트를 연다.
2. 위 한 줄을 말한다. 에이전트가 파일 수정 → 검사 → STATUS·project.json 갱신 → 커밋 → push까지 한다.
3. 1~2분 뒤 https://jinwuuju.github.io/Pharma-Health-Desk/ 에서 확인한다.

### 방법 B — 채팅 AI로 할 때
1. 첨부: 해당 단계의 기획안(`docs/plans/`), `AGENTS.md`, 현재 `site/` 파일 전부.
2. 요청: 아래 단계 카드의 ‘범위’와 ‘완료 확인’을 붙여 넣고, “기존 기능과 저장 데이터를 깨지 말고, 바뀐 파일 전체를 출력해줘”라고 한다.
3. 받은 파일로 교체한 뒤 터미널에서:
```
cd ~/'제약헬스 기자 데스크'
python3 tools/check_project.py
(cd tools/smoke && npm ci && node smoke.mjs)
git add -A && git commit -m '단계 이름: 한 줄 요약' && git push
```
4. `site/data/project.json`과 `docs/production/STATUS.md` 갱신도 잊지 않는다(AGENTS 3절).

## 매주 콘텐츠 루틴 (W1부터, 주말 60~90분)

1. `git pull`
2. 코스 1: 다음 주 팩(기획안 1의 14.2) → 새 대화에서 감수(14.5) → `data/packs/pipeline/Wnn.json`
3. 코스 2: 다음 주 항목(기획안 2의 18.3) → 새 대화에서 감수(18.6) → 사실 3개 직접 확인 → `data/canon/` → 파생(18.5)·주간 팩(18.11) → `data/packs/healthbeat/Wnn.json`
4. 앱 기본 탑재가 필요하면 `site/packs/`로 복사 → `python3 tools/check_project.py` → 커밋·push
5. 앱에서 백업 내보내기 → 저장소 밖(예: iCloud Drive)에 보관. 저장소의 `backups/`는 git이 무시하지만 공개 저장소이므로 밖에 두는 것을 원칙으로 한다.

## 막혔을 때

- 배포 실패: `gh run list --limit 3` → `gh run view --log-failed` 결과를 에이전트에게 그대로 준다.
- 화면 오류: Chrome에서 ⌥⌘J로 콘솔을 열고 빨간 오류를 복사해 준다.
- 되돌리기: `git log --oneline`으로 커밋을 찾고 `git revert <커밋번호>` 후 push(기록을 지우지 않고 되돌린다).
